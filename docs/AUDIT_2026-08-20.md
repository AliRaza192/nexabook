## 3. Accounting & Financial Integrity

### 3.1 THE core defect — JEs default to `draft` and reports exclude them

| ID | Severity | Location | Finding |
|----|----------|----------|---------|
| ACC-01 | **P0** | `sales.ts:1006-1016` (approveInvoice), `purchases.ts:454-463`, `pos.ts:439-448`, `purchases.ts:813-822` (expenses), `banking.ts:359-369/541-550/959-967`, `sales.ts:3097-3106` (sales returns), `manufacturing.ts:580-589/824-833`, `accounts.ts:231-330` (manual JE) | **Every operational JE is inserted WITHOUT a `status` field.** Schema default is `'draft'` (`schema.ts:901`). No code path ever flips these to `'posted'` (grep confirms only payroll `accounting.ts:306`, opening balances `accounts.ts:443/582`, stock adjustments `inventory-depth.ts:377/407`, and delete-reversal `sales.ts:1420` set `posted`). |
| ACC-02 | **P0** | `accounting.ts:73/137/205`, `reports.ts:78/303/554` | All financial statements filter `status != 'draft'`. **Consequence: approved invoices, purchases, POS sales, expenses, bank entries, and sales returns are INVISIBLE in Trial Balance, P&L, Balance Sheet.** Only payroll/opening/stock-adjustment JEs appear. GL & Cash-book reports (no status filter — `reports.ts:177-213, 2038-2078`) DO include them → **the two report families disagree.** |

### 3.2 Double-entry integrity

| ID | Severity | Location | Finding |
|----|----------|----------|---------|
| ACC-03 | **P0** | `schema.ts:1174-1183` (`journal_entry_lines`) | **No DB constraint** (CHECK/trigger) guarantees debits=credits. Only app-level `validateJournalBalance` (`accounting.ts:39-45`) with `< 0.01` tolerance (accepts 1-paisa imbalance silently). A buggy/forgotten caller = corrupt ledger with no safety net. |
| ACC-04 | **P0** | `sales.ts:1273-1311` `updateInvoiceStatus` | Status-flip bypass: setting `approved` skips JE + inventory + period lock entirely (also SEC-20). |
| ACC-05 | P1 | `sales.ts:1331-1443` `deleteInvoice` | Reversal block (`:1390-1431`) only runs `if (invoice.journalEntryId)`, but `approveInvoice` **never writes `journalEntryId` back to the invoice** → reversal never fires. Deleting an approved invoice restores stock but leaves the JE orphaned and unreversed. |
| ACC-06 | P1 | `purchases.ts:592-720` `revisePurchaseInvoice` | Looks up original JE by `referenceType: 'purchase'` but `approvePurchaseInvoice` created it with `referenceType: 'purchase_invoice'` (`:459`) → original JE never found/marked reversed; the new reversal JE is inserted without status → `draft` → excluded. Net effect: original stays in ledger, reversal vanishes. |
| ACC-07 | P1 | `accounting.ts:73/137/205`, `reports.ts:78/303/554` | Filters use `!= 'draft'` which **includes `'reversed'`**. Combined with ACC-06 (broken reversal pairs), voided/revised transactions still hit the financials. |

### 3.3 Date semantics & period attribution
